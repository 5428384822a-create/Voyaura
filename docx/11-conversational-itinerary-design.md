# 小曦对话推荐与按日行程设计

## 产品分工

小曦对话页负责旅行发现，不承担逐路口导航展示。用户可以告诉小曦出行身份、同行人、目的地范围、天数、预算、兴趣、饮食限制和旅行节奏；小曦负责追问缺失条件、推荐城市与体验，并解释推荐理由。

行程页负责展示已经确认的可执行计划：怎么去、怎么回，以及每天几点到几点去哪里、游玩多久、午餐和晚餐吃什么、景点之间如何移动。高德返回的逐路口转向步骤默认折叠，只保留交通方式、距离和预计耗时。

## 页面输出![1794901231651](image/11-conversational-itinerary-design/1794901231651.docx)

每趟旅行包含以下结构：

1. 往返交通：出发城市、到达城市、车站或机场、出发与到达时间、价格、来源和查询时间。
2. 每日摘要：日期、主题、天气、住宿区域、当日预算和步行强度。
3. 时间线节点：开始/结束时间、景点、建议游玩时长、开放状态、门票、推荐原因和图片来源。
4. 餐食节点：午餐或晚餐时间、当地菜品、餐厅候选、距离、预算和饮食限制匹配情况。
5. 交通段：相邻节点之间的步行、公交地铁、驾车或打车方式，以及高德距离和预计耗时。
6. 备选节点：闭园、下雨、排队或体力不足时可替换的室内/附近方案。

桌面端采用“每日时间线 + 地图联动”；手机端采用单列时间线和吸底日期切换。用户可以展开景点详情、替换节点、调整时段，并导出单日或整趟旅行长图。

## 数据来源与边界

- 高德 Web 服务：城市与 POI 搜索、坐标、相邻节点路线、距离和预计耗时。开放时间、评分和人均消费属于可选字段，缺失时不能补造。
- 天气 Provider：逐日天气、降雨和高温风险，用于室内外节点调整。
- 铁路与航班授权 Provider：真实班次、时刻、价格和余量。尚未接入时只给交通结构和官方/授权平台跳转，不生成车次与价格。
- `china.omuat.com`：可作为带链接、标题、抓取时间的检索参考。公开可访问或允许搜索引擎索引不等于允许复制正文和图片；正式批量收录前需取得许可或确认使用条款。
- 小红书：只处理用户主动分享的公开链接、用户自己的笔记导出或正式授权接口，不批量抓取搜索结果，不绕过登录、验证码或访问限制。
- 图片：优先使用用户照片、明确授权素材、景区官方开放素材或允许再利用的来源；导出图片保留必要署名。

任何推荐都保存来源 URL、来源名称、查询时间和置信状态。模型不能自行生成开放时间、票价、班次、距离、评分或“网红推荐数”。

## 个性化画像

第一版画像使用显式字段，不让模型暗中推断敏感身份：

- 独自、情侣、朋友、亲子或长辈同行；
- 年龄段与行动便利需求；
- 预算、旅行节奏、每日起止时间；
- 摄影、美食、历史、自然、乐园、购物等兴趣；
- 忌口、过敏、素食与清真等饮食要求；
- 必去、避开、可早起、可夜游、可接受打车等约束。

用户可以查看、修改和删除画像。对话中提取的新偏好先作为本次行程条件，只有用户确认后才写入长期画像。

## 规划算法

这不是单纯依靠大模型的问题。推荐和排程采用混合流程：

```text
用户对话
  -> 模型提取结构化需求并追问缺失条件
  -> 检索候选景点、餐食与内容来源
  -> 高德计算候选点之间的交通时间
  -> 约束排程器生成每天的时间线
  -> 模型解释推荐理由并提出可替换方案
  -> 用户确认后保存行程
```

排程约束包括景点开放时间、建议停留时长、午晚餐窗口、每日开始/结束时间、天气、预算、步行强度、酒店位置、必去点和少走回头路。评分考虑兴趣匹配、来源可信度、季节适配、地理聚类、交通耗时、预算和拥挤风险。

MVP 可以先使用地理聚类、最近邻插入和 2-opt 做稳定的确定性排程；需要处理多日时间窗、必选/可选节点和复杂约束时，引入 Google OR-Tools，而不是训练自己的路线模型。LangGraph 只有在工具调用和人工确认分支明显复杂后再评估，第一版不依赖它。

## 长图导出

导出不是直接截取整个应用页面，而是使用独立海报模板。推荐尺寸为 `1080x1440`（每日卡片）和 `1080x1920`（手机长图分片）。每张图包含日期、主题、景点照片、时间线、交通耗时、餐食建议、来源与生成时间；多日行程按天生成多张，避免一张无限长图片难以阅读。

导出内容必须来自已经保存的结构化行程，确保网页与图片中的时间、路线和餐食一致。图片生成失败不能影响行程本身。

## 实施顺序

1. 修正高德 Web Key 数字签名并验收真实 POI 与路线。
2. 建立 `Trip`、`TripDay`、`ItineraryStop`、`TransferLeg`、`MealSuggestion` 和 `Evidence` 数据契约。
3. 将当前行程页改为每日时间线，逐路口导航折叠为交通摘要。
4. 实现景点候选、开放状态、建议停留时间和午晚餐候选。
5. 使用高德路线结果完成单日顺序优化和地图联动。
6. 建立小曦聊天 API、会话存储、结构化需求提取和人工确认。
7. 接入天气、内容检索、铁路与航班授权 Provider。
8. 完成单日/整趟行程长图导出和移动端验收。
