# 第四轮实施与验证记录

基线 `98c5679`，分支 `codex/competition-ui-round4`。原三轮完成后，用户授权继续开发，并明确第四轮方案直接执行、不再征询执行确认。本轮沿用已选择的A视觉，处理跨页面体验与演示衔接。

## 已验证的问题与修复

| 问题 | 本轮结果 |
| --- | --- |
| “我的”只打开连接弹窗，`/account` 是占位 | 新增档案总览、使用引导、实际统计、最近任务及当前能力；未连接时不读私人API |
| 未登录直达故事页只记路由名，城市与日期丢失 | 验证后恢复完整本地路径及查询条件；连接窗口提示将继续的场景 |
| 已有任务需要先找工作台再打开历史 | 总览直接跳到原任务，GET恢复、保留版本，刷新后仍读取同一任务 |
| 输入或故事编辑在导航后丢失 | 统一离开提醒；取消保留输入，主动放弃才导航；浏览器刷新／关闭也有保护 |
| 文字记忆关闭可能丢失尚未保存的内容 | 同一提醒覆盖编辑器关闭；预览仍属于未提交，确认成功才清除脏状态 |
| 嵌套提醒可能与底层弹窗争抢键盘 | 用inert暂停底层焦点管理，默认焦点留在继续编辑；Escape保留原内容 |

## 架构与权限

总览使用现有MapOverview、Agent capabilities、Image styles与Agent runs接口。状态读取相互独立；能力读取失败不挡住历史，旧请求不得覆盖新连接状态。配置可用性不代表在线Provider已验收。

工作台接收原任务ID并恢复输入；读取外部服务和私人记忆的授权均重新关闭，保存仍按原摘要、版本与确认流程执行。路由只传城市、日期与任务ID，不传正文或令牌。未提交内容仅在页面内存中保留，不添加localStorage自动存稿。

本轮不修改后端、数据库结构、依赖锁或云凭证。产品内的保存／删除／费用确认继续遵守原需求；“直接执行”是研发授权，不把它解释为后台代替用户保存私人记录。
