# Voyaura 第二轮前端改稿审阅

日期：2026-11-23。基线：用户选定方案A后的 `69879b4`；独立分支：`codex/competition-ui-round2`。

## 实际交付与设计取舍

沿用方案A的暖白底、橙红品牌与明亮摄影，完成“规划输入 → 小曦执行 → 行程结果 → 核对保存”的第二轮改稿。输入按旅行想法、基本安排、偏好三组呈现；时间与必去地点等细项折叠，兴趣可点选且最多三项。首页已有城市与想法继续带入。桌面右侧展示本次目的地灵感、已填日期和节奏；这些信息来自表单，不冒称模型已经规划。

有实际地点安排后收起长表单，显示本次旅行条件与“调整旅行条件”入口。每日安排、地点地图、执行记录三个视图真实可切换；日程与地图共用所选日期，键盘方向键／Home／End与焦点同步。时间线保留地点来源、停留时长、交通未知信息；费用只汇总已知景点票价。原接驳工具移入条件栏，避免悬浮按钮遮挡内容。

流程阶段依据真实请求与服务端状态显示，不设置假进度百分比或伪造已完成工具。任务完成后保留实际调用、失败、重试与检查记录。私人保存仍先从服务端读取当前版本摘要，条件草案需主动勾选，才可确认；确认区域会获得键盘焦点。重新生成时显示等待状态，不沿用上一份已保存任务的完成阶段。

恢复历史任务后，“调整旅行条件”会恢复该任务的日期、城市、预算、兴趣和候选地点；外部工具授权保持关闭，需重新选择。缺信息或失败时保持可补充输入。真实验收发现：后端可能在 needs_input 状态返回空日期结构，现已修复“有日期即视为计划”的误判，防止收起待补充表单。
