# 第三轮：旅程、记忆与创作

沿用用户已选定的A方案：暖白底、橙红主操作、浅纸色档案、清晰字号与留白。开发基线 `0a4a45d`，分支 `codex/competition-ui-round3`。本轮是可操作产品改稿，不是新增一组静态概念图。

## 从概念图到当前产品

| 概念参考 | 本轮实现 | 实际边界 |
| --- | --- | --- |
| 02 地点级旅行记忆 | 城市索引、日期时间线、文字与影像视图，编辑／上传／创作入口 | 当前数据仍以城市为单位，未新增POI级记忆关联、语音转写 |
| 06 图片工作台 | 原照片来源、生成历史、真实状态、对比与下载，技术信息按需展开 | 沿用现有影像API；当前生成服务未连接，不展示虚假作品 |
| 08 跨旅程记忆重访 | 城市／省份搜索、年份活动筛选、独立记忆书架 | 年份筛选城市索引；完整城市档案保留全部历史记录 |

## 可操作的变化

1. “旅程”分为旅行足迹与城市记忆。地图与城市档案并列；地图缺Key时，仍可直接打开已有档案，诊断信息收进“查看地图状态”。未绘制虚构行政区底图。
2. 空档案具有真实入口。手动选城提供六城本地索引，调用原有预览／确认接口；选择与预览均不点亮城市，只有主动确认才写入。来源明确为手动声明，不假称设备定位。其他城市依赖原在线搜索。
3. `/journey/stories` 成为独立记忆书架。按城市打开日期与文字，点击“整理这座城的故事”才进入编辑流程。带入已有记忆日期时，私人记录读取授权仍默认关闭。
4. 城市档案支持键盘焦点、Tab循环和Escape关闭；文字编辑器打开时，底层抽屉暂停交互。首次／最近时间标为“记录”，避免把手动确认时间冒充实际初次抵达日期。
5. 文字时间线中直接提供照片“风格创作”，无需先发现影像标签中的图标。创作页空状态提供自己的照片入口；装饰摄影明确标为灵感参考，与私人作品区分。
6. 创作服务不可用时保留真实说明与已有历史；风格目录失败不再阻塞历史读取。快速切换收藏时忽略旧请求，离开页面后停止轮询。

- `before/`：修改前当前服务的六张桌面／手机截图，API写请求为0。
- `after/`：修改后当前服务在1440、768、390、320四屏宽的只读截图。是否有城市，以真实用户档案为准，不填入测试数据。
- `journey-screenshots/`：独立测试库中主动录入“本地验收·非真实旅行”文字后，实际HTTP操作产生的预览、档案与故事截图。
- `flow-screenshots/`、`practice-screenshots/`：原行程／故事／演练链路的当前回归证据。原轮次证据完整保留。
